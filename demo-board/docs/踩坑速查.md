# Demo 板死机/异常速查（三种历史案例 + 触发链路判读）

> 每条: 日志特征 → 根因 → 处置。排查新死机时先对照这里，都不匹配再深挖
> （方法论见 main 分支 `porting/firmware/踩坑总结.md`）。

## #1 录音池溢出断言（CCC 时代, 已修）

- **日志特征**: `aud_sv_datamgr.c:1119` 断言 → 三核崩 → 50s WDT 复位循环；出现在说话/开麦后
- **根因**: demo 板电源管理把 dcore 降到 16/32MHz，Silero 慢 4-7 倍追不上实时，240ms 池积压爆
- **处置**: `wq_silero_vad.c` init 时 `dfs_request(WQ_FREQ_192M, 0)` 并持有（CCCv2 起）
- **判读**: 日志应有 `[DFS] core2 send request 192`；没有就是修复丢失

## #2 开机即死机循环（CCCv3, 已修）

- **日志特征**: 每次上电 ~3s 处 `[auto]m_ring.c:985 Asserted!`（dump 里 rd=乱值）→ crash dump → 复位循环
- **根因**: 上次会话 APP 使能 VAD 被 factory_mode **持久化进 flash** → 下次上电 3.1s 即自动开麦起流；
  而 dcore 正被 HIL 自测独占数秒 → acore 建 datapath ring 时读到未初始化的远端读指针
- **处置**: entry.c 停用 HIL 钩子（`#if 0`）；复验 HIL 前先把板上 VAD gate 清 0
- **教训**: 测试钩子也是行为；板侧 flash 持久化状态是"隐形配置"，同一固件不同历史行为不同

## #3 长录音 WDT2（CCCv4, CCCv5 修复待验）

- **日志特征**: 说话触发录音成功（`hit:1` → `app_record RECORDING`）后 ~16s，`WDT2 is timeout`
  → `DCORE crash`，PC 落在厂商 opus `compute_mdcts`
- **根因**: **算力超支**——全速 Silero 31ms/窗≈97% 实时预算，叠加本地录音的 opus 编码后
  管线只跑到实时的 62%（30.5s 仅完成 593 窗），积压到看门狗饿死。原厂 VAD <1ms/窗故不崩
- **处置**: CCCv5 录音态降载——首次命中后每 3 窗推理 1 窗，连续 64 受评窗 p<0.1(≈2s)退出降载
- **验收**: 录音期 `[SVs]7-done` ≈10.4 行/s（=31.25÷3）且录音撑 >60s；hit 链路不回退

## 触发链路日志判读（两段式唤醒, 按时间序）

```
[vad_record] gate N x -> 1 wanted 1     ← VAD 使能(APP 或持久化)
[VAD] tvad detect irq                    ← 硬件 TVAD 先响(常开低功耗)
[VAD] gvad window arm seq:N              ← 开候选窗(2000ms)
[DSP] create mic stream / wq_sw_vad_init ← dcore 建流, Silero 上线
[DFS] core2 send request 192             ← 192M 持有生效
[SVs]7-done p=xxxx                       ← 逐窗概率(p=400≈0.04 静音, 说话应 >5000)
wq_sw_vad_process hit                    ← Silero 命中(cb(1))
[VAD] VG4 voice ingress accept:1 hit:1   ← acore 接受(★hit:0=没触发, 与 p 无关)
[vad_record] voice hit start accepted    ← 录音会话受理
app_record 3(STARTING) -> 4(RECORDING)   ← 本地录音真跑起来了
```

**关键判据**: p 很高但 `candidate timeout hit:0` = 命中没送到 → 查返回值契约
（必须逐帧回报最近窗判定，见 wq_silero_vad.c 尾部注释）；hit:1 但无录音 → 查 acore
candidate/record monitor 状态机。

## 已知边界（报告厂商前先看）

- `candidate timeout claim:1 hit:0`：候选窗 2s 内没人说话，正常回退非故障
- `release stream N repeated error!`：recordsv 转场日志，CCCv4 单独出现时尚无实害
- factory CLI 的 MODE_SET 会清 VAD gate 持久化（c60-c67 KV）——测试环境变动先想到它
