# 原厂基础上的优化方向（2026-10-20 A/B 实测后定案）

> 背景：同板 A/B（CCCv12 Silero vs VVV 原厂复刻，各 17 分钟自然使用）实测
> **两版体验差距不大**（录音 12:12 打平、均零崩溃、原厂也有停录失败一次）。
> 结论：**当前性能差距不足以单独支撑换内核**——优化主战场从"换更强 VAD"
> 转向"**在原厂基础上做场景策略 + 状态机 + 前级门控**"，全部零/低功耗。
> 本文档结合两个月全部踩坑史，给出可落地的执行清单。

---

## 一、A/B 实测数据（为什么转向原厂基础优化）

| 维度 | VVV 原厂 WebRTC | CCCv12 Silero |
|---|---|---|
| 录音次数/稳定性 | 12 次 / 零崩（1 次停录失败） | 12 次 / 零崩 |
| 正常音量触发延迟 | ~0.7s | **0.3-0.5s 更快** |
| 轻声触发 | ~0.7s | 2-3s（LSTM 冷启动，固有代价） |
| 抗噪误触发 | 板上未分出（PC 差 4-6 倍） | 板上未分出（PC 强） |
| 功耗 | **64M 原生** | 192M 持有（B 线优化中） |
| 可调性 | 0/1 输出，难做精细策略 | 连续概率 p，规则空间大 |

判读：安静场景两者相当 → **性价比最高路线 = 原厂内核 + 我们已验证的后处理技术**。
Silero 线保留为"嘈杂场景档"或二阶段确认器，不整体替换。

## 二、可落地优化清单（按性价比排序）

### P1. 收紧 TVAD 前级门控（最优先，零算力）

吹气/风噪实测会穿透两层软件闸门（TVAD 只看能量 100% 放行）。根治在第一道门：
- 查厂商 TVAD 门限/频带参数（`VG3 config mode:3 front:10ms`，ro_cfg 层）
- 抬高门限把吹气/风挡在系统外；**小心：不能太严否则漏低音量人声**（原则见 P4 前级）
- 落地形式：ro_cfg 或 defconfig 参数，无需改代码

### P2. 触发后复核窗（300-800ms，只动状态机）

不要一触发就生成用户可见录音：
- 触发 → 候选录音态（预录缓冲已有，厂商 preroll 240ms 在用）
- 复核期内概率快速跌落 / 无稳定语音 → 丢弃，不生成文件
- 整段短于最小时长（如 1.5s）且无稳定段落 → 不提交
- **已验证素材可复用**：CCCv8 的 rms 骤降指纹（81021→413 降 197×）、
  v10 能量门控（rms<min(1.6×nf,600) 判静音）、120s 硬顶——全是复核逻辑的零件

### P3. 连续误触发冷却

- 连续 N 次候选超时（无 hit）→ 进入 3-5s 冷却，TVAD 不再开窗
- 厂商已有原生参数 `CONFIG_APP_VAD_INVALID_CANDIDATE_COOLDOWN_MS`（当前=0，一行可调）
- **坑**：冷却伤轻声重试（第一句没触发、第二句被冷却吞掉）——需"连续失败≥2 次才启动冷却"折中
- 收益：风噪/持续摩擦环境下防候选窗雪崩（每个窗 3.5s 高负载，风噪下功耗翻倍）

### P4. 场景 profile（利用已有状态，零新传感器）

| 场景 | 状态来源（已有） | 策略 |
|---|---|---|
| 静止/桌面 | rms 方差低 | 阈值正常，响应快 |
| 走路/晃动 | rms 形态震荡（[SVf] 可测） | 阈值提高，确认帧数加倍 |
| 充电 | 充电状态（日志 `[app_bat] charging`） | VAD 关闭或最保守 |
| 包内/遮挡 | rms 整体闷低 + 高频缺失 | 提高阈值或暂停 |
| 音乐播放 | 厂商 music gate（已存在，music:1 时暂停 VAD） | 已有，确认生效即可 |

全部判据来自现有传感器/状态，不加常开计算。

### P5. 轻量 hard-negative 特征（可选，最后做）

峰均比 / 能量斜率 / 频带占比 / 概率方差——**板上实测教训**：MUSAN 上这些单帧特征
与语音分布重叠（无干净分界），只有 rms 骤降指纹（脉冲型）实测有效。做之前必须
先用 P6 的真实样本回归证明区分度，**不预先堆规则**。

### P6. 真实误触发回归集（一切调参的前置）

- 正样本：真实说话（正常/轻声/远场/短句/走路说）各 20-30 条
- 负样本：吹气（近/远/缓）、摩擦、拖拽、碰撞、包内、风噪、电视外放各 20-30 条
- 采集方式：板上 [SVf] 特征行已内置（p/rms/nf/skip/veto 逐窗），跑一轮动作即得数据
- 每次调参输出：误触发/h、人声召回、短句召回、触发延迟 P50/P95、句首保留率、无效录音时长
- **先测后调**：这个月盲调的教训（0.5→0.45 阈值、200→120ms 确认）有效但都是猜-验循环，
  有回归集后是数据驱动

## 三、结合踩坑史的执行约束（违反必翻车）

| 约束 | 来源坑 |
|---|---|
| 任何新逻辑先过"窗完成率≥95%"（数 [SVf]/hit 行 ÷ 秒） | v4 WDT2：算力超支 62% 崩 |
| 不引入"按时间退出/切换"的状态（句间停顿是常态） | v5：2s 静音退出降载 → 录音中途回全速超支 |
| 流生命周期 ≠ 会话生命周期，DFS/资源绑定要对齐 | v7→v11b：候选窗销毁重建间隙掉频到 16M |
| 录音启动瞬间是危险窗口（三重叠加），新负载要避让 | v12：冷读+opus+提示音 100ms/窗池溢出 |
| 覆盖写状态前想清楚执行顺序（infer 前后） | v10：能量门控被推理输出覆盖，从未生效 |
| 板上 flash 持久化状态是隐形配置（factory gate/KV） | v3：持久化 VAD gate 开机自启 × HIL 独占 dcore 竞态 |
| 测试用例必须含句间停顿/断续（真实语音形态） | v6 贴地运行 193 条告警被短测试掩盖 |

## 四、与方案商的分工建议

| 事项 | 责任方 | 说明 |
|---|---|---|
| TVAD 门限参数位置/可调范围 | 方案商 | P1 的前置 |
| NS 噪声抑制组件（吹风机+人声场景唯一解） | 方案商 | demo 管线无 NS，实测 SNR<-15dB 无解 |
| 音乐暂停 VAD（music gate）生效确认 | 方案商 | 代码已存在，需确认配置开启 |
| 复核窗/冷却/profile/回归集 | 我们 | 全部可在我们 wrapper 层实现 |
| opus@64M 实测预算（录音态降频前置） | 双方 | 刷原厂固件录长音数吞吐率即可 |

## 五、执行顺序

```
P6 回归集(先测) → P1 TVAD门限(厂商参数) → P2 复核窗(复用已验证零件)
→ P3 冷却(一行配置+折中逻辑) → P4 profile(按回归集数据逐档定参)
→ P5 特征规则(仅当回归集证明区分度) → 功耗B线(96M录音态/功率仪)穿插
```
