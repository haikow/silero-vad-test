## 二、提请清单

### P0 —— 阻塞"NN 编译到 NPU"(VAD 移植主线)

**P0-1 NPU 使能的 WQ7036 Xtensa 核配置(最关键)**

- 为什么:现配置 `wq_hifi5_asic-params` 第 26 行 `HasXNNE = 0`(实测),XNNEC(NPU 编译器)
  找不到 NPU 信息报 `neo params file is not present`(已直接复现;反汇编确认其查找链:
  `--neo_params_file` 参数 / cfg `[system] neo_params_file` / cfg `neo_params` /
  默认 `<config>/<核名>_neo-params` / 核参数文件 `XNNEVersion` 行,五层全落空)。
- 期望内容:params 文件应含 XNNC 实际解析的这些字段(字段名从 XNNC 代码提取,可作为验收标准):
  `XNNEVersion / XNNEIPVersion / XNNENMacs / XNNEUBufSize / XNNENumUBUFBanks /
  XNNEBaseAddress / XNNEFP16En / XNNEInt4En / XNNESparseComputeEn / AXI 位宽` 等;
  如单独交付 `<核名>_neo-params` 与 controller-params 文件亦可(告知放置路径约定)。
- 验证方法(拿到后 5 分钟可验):把文件放入 XtensaTools config 目录,重跑
  `xnnc.py -c silero_vad.cfg`,不再报 neo params 错误即通过。
- ⚠️ 必须同时确认:**WQ7036AC 的 NPU 是哪一代 —— NNE110(1xx)还是 Neo2x0(2xx)?**
  XNNC 对两代使用不同的 include 配置(NNE110.cfg / Neo2x0NPU.cfg)和不同的 scheduler,
  拿错代际的配置整套都白拿。

**P0-2 Xtensa 工具 RJ-2024.3 + patch 916454(Linux x86-64 版)**

- 为什么:neuroweave_ug §2《Installing NeuroWeave SDK》原文指定——"Xtensa RJ-2024.3 with
  patch 916454 and above for Neo NPU"(另荐 Xplorer 10.2.3)。RI-2020.4(2020 年)早于
  Neo NPU 工具集成年代,固件线可用、NN 线不保证兼容。
- 期望内容:RJ-2024.3 Linux 安装包 + patch 916454;若物奇内部 NN 线实际用其他版本,
  以他们的为准并告知版本号。
- 注:我们已在容器中验证 xt-xcc(RI-2020.4)可运行,替换/并存无环境障碍。

**P0-3 Xtensa license(软件编译授权)**

- 为什么:物奇下载服务器上有 Cadence license server 软件
  (`license_srv/xtensa/linux/licserv_linux_x64_v11_15.tgz`),说明 XtensaTools 正式编译
  需要 license;`xt-xcc --version` 不查 license,我们尚未触发,但 gen_code 后的固件库
  编译大概率会要。
- 期望内容:license 文件(或激活方式)+ 对应我们机器的 hostid 要求(容器/VM 环境
  hostid 如何算,建议提供 flexlm node-locked 或 server 两种选项);
- 顺带确认:`xtensa-wuqi-elf-gcc 12.2`(GCC 版)是否免 license 可用于 NN 生成代码编译。

### P1 —— 阻塞"VAD 集成进固件"

**P1-1 物奇固件 SDK(wq-audio / wq-adk)完整包 + 使用文档**

- 固件同事工程里已有 `wq-audio/wq-adk`(examples/glass 等),但算法侧需要:
  - **WUQI Audio Pipeline 框架文档与 API**(对外开放的第三方算法接入框架;公开渠道
    eet-china 2024.11 有介绍,需正式文档)——VAD 替换原厂 VAD 的挂接点;
  - 原厂 VAD 的**接口约定**(初始化/逐帧调用/输出事件),便于等价替换;
  - 原厂 VAD 的**资源占用参考值**(cycles/内存/功耗),作为 Silero 版本的对照基线;
  - examples/glass(AI 眼镜)工程作为参考(它就是带语音 AI 能力的整机示例)。

**P1-2 Neo NPU 驱动在 WQ7036 固件里的集成范例**

- 为什么:XNNC 包自带 xnne_driver 源码,但芯片侧的初始化序列、内存分配、与 Audio
  Pipeline 的对接需要物奇的集成参考(他们自家 AI 算法就是这么接的)。
- 期望内容:NPU 驱动 bring-up 示例工程或他们某个 NN 算法(如原厂 VAD/唤醒词)的
  固件集成代码(哪怕二进制库 + 头文件也行)+ DSP 子系统内存映射/linker script。

**P1-3 XNNC 在 WQ7036 上的物奇侧应用笔记(若存在)**

- 你们既然交付 XNNC 3.2.2 + neuroweave 文档,内部大概率有 WQ 专属的适配说明
  (NPU 代际、推荐 cfg、已知问题)。有则直接给,能省我们大量试错。

### P2 —— 联调/验收阶段需要

**P2-1 开发板 + 烧录调试工具链**:`wq-debug-tools`(物奇服务器上可见此仓库)+ 烧录流程
文档 + UART 调试口约定(固件在环测试协议要用,UART0=GPIO01/GPIO02 已知)。

**P2-2 XTSC 仿真模型(可选)**:HiFi5+NPU 子系统级仿真(文档 §10.4.5 提到 xtsc-run),
可在无板阶段跑周期数评估;若受管制可不提供,以板上实测替代。

## 三、需要 FAE 明确回答的问题(随清单一并提)

1. WQ7036AC 的 NPU 是 **NNE110 还是 Neo2x0 系**?对应 XNNC 配置用哪个 include?
2. 物奇自家的原厂 VAD / 唤醒算法,在 WQ7036 上是 **NPU 跑还是纯 DSP 跑**?
   (若纯 DSP:他们如何绕开 XNNC 3.2.2 流式 LSTM 的 memref bug——我们实测
   纯 DSP + streaming 路径在 xnnc-opt 段形状不匹配崩溃,报错原文可提供)
3. NN 编译线用的 Xtensa 工具确切版本(RJ-2024.3?)+ 是否与 XNNC 3.2.2 配套发布?
4. Xtensa license 的发放形式与数量(编译机 + CI 机)。
5. `xtensa-wuqi-elf-gcc` 与 XtensaTools xt-xcc 在你们固件构建里各承担什么?
   (影响我们固件集成时选哪个编译器)
