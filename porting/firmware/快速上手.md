## 2. 基线固件与产物

1. **先刷 S 包**(`integration/wpk/glass-silero-S-*.wpk` = 纯官方 ADK+板 ro_cfg)
   确认三核正常启动——这是"我的环境没问题时"的对照点
2. 再刷 **NN 包**(数值验收版)或 **RR 包**(当前最优 96.7ms)复现验收
3. 自编包命名:`glass-silero-<编号>-7036AC-0.0.0.0.wpk`,放 `integration/wpk/` 留档
4. **ro_cfg 替换**是打包的一部分:wpk 是 zip,`zip xx.wpk ro_cfg.bin` 原位换工厂版
   (哈希 b5c48a5e…,来自 v0.9.2.8 wpk)
5. 出包三验:`xt-nm glass_dcore.elf | grep sv_process` →
   `validate_dcore.py <bin>` 段链 PASS → 上板

## 3. 开发主循环(每次改动的标准流程)

```
改 silero_vad.c(等) → Docker scons -j16 → validate_dcore.py PASS
→ zip ro_cfg 出 wpk → 刷板 → 串口从上电抓日志(≥25s, 覆盖 [SHIL] 全程)
→ hil_parse.py 对拍(≤0.1 过线; 当前水位 0.0001) → 入库(wpks+文档)
```

- **单变量原则**:一次改动一个包一个结论;两步以上合成一个包,出问题无法归因
- 数值对拍是唯一验收:**推理≠直觉**——"数学上应该等价"必须过板子
- HIL 钩子(0004)每次上电自动跑 40 窗,是免费的回归测试;量产版去掉即可
- 阶段计时看 `[SVs]1..7` 时间戳(前 2 窗),概率看 `[SVs]7-done p=`(每窗)

## 4. 坑速查(完整版+案例见踩坑总结,这里只列"会咬人"的)

| 类 | 一句话 |
|---|---|
| 基线 | 板子=glass-stereo-dac(1.4.0.69);在 ai.recorder/1.3 上做任何事都是白费 |
| NNLib 布局 | matmul 输入 [T][IC];conv1d kernel 按 [OC][ICW_pad×2] 读(直传必越界);**分块调用输出行距=out_channels≠目标行距**(先写连续 scratch 再拷回);零输入时以上全部隐身 |
| 算法语义 | ONNX 每块 dw→**ReLU**→pw(漏了静音窗 p 偏 0.3);**C-vs-C 假金标**(对照物必须 onnxruntime 直出);HIL 音频 ×**32768**(×32767 每样本偏 1 LSB) |
| 内存/性能 | inst_xip(0x26200000)是**取指专用**(数据访问崩);data_xip ~5.5MB/s;PSRAM≈flash(4.5MB/s)只当容量用;**暂存大块前按 HIL(preset 前)/量产(preset 后)两条路径分别核预算**(preset block0 要 216KB)——KK/PP 两次同款断言 |
| 平台 | printf 是空桩(用 DBGLOG_INFO);HIL 钩子放 app_main_entry **之前**;DBGLOG 连发会丢行(门控前 2 窗);WDT2 连跑 ~17s 咬(显式 `wq_wdt_do_feed()`);conv1d state=环形缓冲 ≥2.1KB |
| 工具链 | scons 输出进管道会 SIGPIPE 杀构建;改 defconfig 后必须 `scons --defconfig=` 重新生成;Docker virtiofs 缓存陈旧(容器内原位重写文件解);全清 build 后先 `--defconfig` 再 scons |

## 5. PC 金标工具(`integration/`,clone 即可跑)

| 工具 | 用途 |
|---|---|
| `hil_parse.py` | **验收主工具**:串口日志 → 逐窗概率 vs golden_prob.f32(支持 mid-run 抓取的相位锚定) |
| `validate_dcore.py` | dcore 镜像段链校验(打包是否损坏) |
| `ii_expect.py` | 板端语义预测表:numpy 严格复现 C 流水线(改算法前先在 PC 预测) |
| `golden_q.py` | 输入量化对照实验(区分"输入表示"vs"数学 bug") |
| `gg_golden.py` / `gg_compare.py` | STFT 层金标与对照 |
| `gen_hil_audio.py` | HIL 音频头再生成(**必须 ×32768**,断言无损) |

数据依赖已入库:`porting/firmware/{m.onnx, golden_x.f32, golden_prob.f32}`。
这些工具都是调试期在本地生成、后补入库的——**改算法时先用它们在 PC 出预期表,
再上板对拍**,能省一半烧录周期。

## 6. 性能现状与 <32ms 路径

窗 1 稳态 96.7ms = STFT(FFT) 9.7 / norm 5.9 / first 30 / enc 14.8 / LSTM 35.7 / dec 0.4。
三步已做:FFT 替 STFT 卷积 → LSTM matXvec+R 暂存 TCM → 1x1 matmul。
**剩余无法自行压缩的都是权重 flash 流量**(LSTM W 128KB + first/enc 75KB,TCM 运行时
余量 69KB 装不下)。<32ms(真麦实时)需要厂商 preset 重配释放 ~140KB TCM → 全权重
暂存 → ~25-30ms。预算表/实测数据已备齐(见 NNLib优化方案.md §7)。
