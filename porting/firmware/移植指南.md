# Silero VAD 移植指南 —— WQ7036AX/AC 从零到固件(全记录)

> 定稿:2026-09-24。本文是移植工作的总纲:改哪些文件、怎么构建、怎么验证、踩过哪些坑。
> 细节展开见同目录 `integration/README.md`(wq-adk 集成)、`integration/烧录硬件指南.md`(烧录/接线)、
> `integration/wq_burn.py`(Mac 原生烧录器)。桌面算法实现在上一级目录。

## 0. 成果速览

| 项 | 结果 |
|---|---|
| 替换对象 | 原厂 WebRTC VAD(闭源 `libwq_sw_vad.a`)→ **Silero VAD v4(纯 C99 源码,float)** |
| 数值验证 | C 实现 vs onnxruntime:40 窗最大偏差 **7.7e-7**;攒帧管道纯度 0.0;int16 量化损失 1.7e-2 |
| 固件 | 7036AC 与 7036AX 双芯片 wpk 产出并**实机烧录成功**(2026-09-23) |
| 侵入性 | **processor 层零改动**——复用原厂 VAD 的 5 函数接口,上游(vad_stream/sw_vad)无感知 |
| 资源 | 权重 601KB(链 icache 段) + 静态缓冲 26KB + 句柄 3KB;计算 ~70 万 MAC/窗 |

## 1. 路线定案(为什么这么走)

1. **放弃 NPU**:原厂拒提供 neo params(`wq_hifi5_asic-params` 中 `HasXNNE=0`),XNNC 3.2.2 又有流式
   LSTM 编译 bug(`memref.copy` 崩溃)→ NPU 路线在公开资料边界内不可行。
2. **纯 DSP float C**:HiFi5 有 FPU,Silero 网络很小(~70 万 MAC/32ms 窗),C99 直接写。
3. **接口仿真而非重接**:原厂 VAD 对外就 5 个函数(下表),全部按原签名实现,processor 管线
   (mirror→shaper→sw_vad→kws→breaker)一行不用改:

| 原厂函数 | 我们的实现 |
|---|---|
| `wq_get_sw_vad_hd_size()` | 返回 `sizeof(wq_silero_hd_t)`(3KB) |
| `wq_get_sw_vad_scratch_size()` | 返回静态缓冲需求(26KB) |
| `wq_sw_vad_init(hd, scratch)` | LSTM h/c 状态清零 + STFT 状态复位 |
| `wq_sw_vad_process(hd, pcm)` | **320 样本(20ms)进,内部攒到 512 样本窗**(320×8=5×512)后推理 |
| `wq_get_sw_vad_lib_version()` | 返回 "silero-v4" |

## 2. 需要改什么文件(核心清单)

### 2.1 新增(从本仓库拷入 SDK,共 11 个文件)

| 本仓库文件(porting/firmware/) | SDK 目标位置 | 作用 |
|---|---|---|
| `silero_vad.c` / `silero_vad.h` | `components/audio_algorithm/processor/src|inc/` | 算法本体:STFT+归一化+CNN+LSTM+解码,`sv_process()/sv_reset()` |
| `silero_vad_weights.c` | 同上 src | 601KB 权重,`gen_weights.py` 从 ONNX 生成;**`SV_WSEC` 宏仅 Xtensa 下链 `.icache.literal` 段**(7036AX DRAM 768KB 放不下,详见 §5) |
| `silero_vad_consts.h` | 同上 inc | 归一化常数(SV_NORM_MUL/ADD)等 |
| `wq_silero_vad.c` / `wq_silero_vad.h` | src / inc | WQ 5 函数接口 + 320→512 攒帧 |
| `wq_sw_vad.h` | inc | 接口头(内容同原厂 lib 头,让 processor 层无感) |
| `integration/wq_gcc_shim.c` | src | **仅 GCC 构建需要**:`_Assert/__recipsf2/__ieee754_sqrtf` 垫片(链接 XCC 预编译库用);xt-clang 构建可不放 |
| `integration/hil/wq_silero_hil.c` + `silero_hil_audio.h` | src | HIL 自检:上电跑内嵌 golden 40 窗,`[SHIL]` 逐窗概率出调试串口(生产版可移除) |
| `integration/hil_parse.py` | 不入 SDK(PC 端) | 串口日志 vs `golden_prob.f32` 验收,线 0.1 |

> SConscript 自动扫描 `processor/src/*.c` 编入,**不需要改构建脚本**。

### 2.2 修改(共 5 处)

| SDK 文件 | 改动 | 原因 |
|---|---|---|
| `components/audio_algorithm/lib/wq_sw_vad/` | 整目录移到 `lib_disabled/` | 停用原厂预编译库;**移回即回退**,是最干净的开关 |
| `examples/glass/config/<芯片>/defconfig.silero` | 新增(仓库 integration/config/ 有现成) | 见 §2.3,两个芯片基线不同 |
| `examples/glass/config/<芯片>/flash_layout.json` | dcore 分区 **300 → 400 扇区** | 权重 623KB 进镜像后 dcore 1.43MB > 原 1.17MB |
| `wqcore/tools/SCons/xtensa_tools.py` | 3 处 `-Werror` 后追加 `-Wno-error=stringop-overflow/maybe-uninitialized/array-bounds` | 旧 SDK 代码的 GCC12 误报(仅 GCC) |
| `apps/dcore/entry/entry.c` | `app_main_entry()` 后加 `wq_silero_hil_selftest()`(用 `#if is_defined(CONFIG_AUDIO_VAD_ENABLE)` 包住) | HIL 钩子 |

### 2.3 defconfig 要点(两芯片不一样,别照抄!)

- **7036AC**(`integration/config/7036AC/`):基于 ai.recorder 基线 + `CONFIG_VAD_ENABLE=y`
  + `CONFIG_RING_ALLOCATE_CFG=2` + `CONFIG_PIPELINE_STREAM_MAX_NUM=20` + `CONFIG_XT_TOOLCHAIN_GCC=y`
- **7036AX**(`integration/config/7036AX/`):基于**原版 stereo.dac 复制,只改 `CONFIG_XT_TOOLCHAIN_GCC=y` 一处**
  (VAD 开关 stereo.dac 原本就有)。
  ⚠️ 教训:照搬 7036AC 的裁剪项到 7036AX 会触发 defconfig 依赖级联报错——**每芯片用它自己的原厂基线做最小改动**。

### 2.4 权重再生成(换模型/改版本时)

```bash
pip install onnx numpy && python3 gen_weights.py silero_vad_v4_float.onnx
# 产出 silero_vad_weights.c + silero_vad_consts.h, 直接覆盖
```

## 3. 构建步骤(容器内)

```bash
# 环境: Mac 上 scripts/start-env.sh(Colima VZ+Rosetta)或任意 x86-64 Linux + docker
docker run --platform linux/amd64 -v <sdk>:/work -v <wqcore>:/opt/wqcore \
  -e WQCORE_TOOLCHAIN_PATH=/opt/wqcore/toolchain -w /work/wq-audio/wq-adk/examples/glass \
  wq-build:latest bash -c \
  'scons --defconfig=config/7036AX/defconfig.silero && scons -j16'
# 7036AC 同理换路径
```

- 工具链:WQCORE(RI-2020.4 + xtensa-wuqi-elf-gcc 12.2 + riscv64 10.2),GCC 为软浮点——**功能验证够用,
  实时性不足;生产固件交物奇用 xt-clang 重编**(见 integration/README 交接说明,源码零适配)。
- 产物:`build/<芯片>/silero/*.wpk`(zip 包:三核镜像 + memory_config.json 烧录布局 + tone/ro_cfg)。
- **改过段属性/defconfig 后必须 `rm -rf build/<芯片>/silero` 全清重编**——旧缓存会把已停用的
  WebRTC 符号链回来(实测踩过)。
- 验证镜像:`nm <core>.elf | grep sv_process` 有符号、`grep WebRtc` 零命中 = 替换成功。

## 4. 验证体系(三层)

1. **桌面层**(Mac 直接跑,不入 SDK):`make test` → `test_ref` 40 窗 vs ORT 基准(<1e-3 即 PASS,
   实测 7.7e-7);`test_wq` 攒帧管道纯度 + int16 量化损失(实测 0 / 1.7e-2)。
2. **符号层**:三核 elf 里 Silero 符号在、WebRTC 清零。
3. **上板 HIL**:上电自动 `[SHIL] begin windows=40` → 40 行逐窗概率 → `end`;调试串口
   **2,000,000 8N1** 抓取后 `python3 hil_parse.py <日志> golden_prob.f32`,**验收线最大偏差 <0.1**
   (判读:<0.01 理想 / 0.01-0.1 可接受 / >0.1 环境问题 / 无输出=接线或未开机)。
   无麦克风也能验——golden 音频内嵌固件自回环。

## 5. 已知坑全记录(按踩中顺序)

| # | 症状 | 根因 | 解法 |
|---|---|---|---|
| 1 | C 实现概率和 ORT 对不上 | STFT 是 reflect pad(96,96) 出 **8 帧**;归一化减项是全局标量;conv1x1 输入布局 [C][T] | 逐节点转写 + ORT 中间张量 dump 三方对照逐级二分 |
| 2 | GCC12 编 SDK 报 stringop-overflow | 旧代码 GCC12 误报 | xtensa_tools.py 三处 -Wno-error |
| 3 | 链接缺 `_Assert/__recipsf2/__ieee754_sqrtf` | XCC 预编译库跑在 GCC 运行时上 | wq_gcc_shim.c 垫片 |
| 4 | dcore 镜像 1.43MB 超分区 | 300 扇区只装 1.17MB | flash_layout dcore→400 |
| 5 | 烧录工具 2 秒报错退出 | **固件编成了 7036AC,板子是 7036AX** | 按实际芯片重编(见 §2.3) |
| 6 | 7036AX 链接 DRAM 溢出 84KB | 623KB 权重 + stereo.dac 代码 > 768KB DRAM | 权重链 `.icache.literal`(1MB 空闲区),`SV_WSEC` 宏实现 |
| 7 | 改段属性后 WebRTC 符号复活 | build 缓存 | 全清重编 |
| 8 | defconfig 照抄另一芯片炸依赖级联 | 配置项依赖不同 | 每芯片用原厂基线最小改动 |
| 9 | 烧录 `send ram fail: TIMEOUT` | 芯片未进下载模式(GPIO_101 上电为高)或串口未通,与 wpk 无关 | 见烧录硬件指南 §2/§3 |
| 10 | 日志口(GPI040/41 预留串口)零字节 | **Dmic4 导通跳线帽占用复用引脚** + 产线固件可能关日志 | 拔 DMIC4 跳帽;或用母板内置串口(Demo 板 TypeC 直连) |
