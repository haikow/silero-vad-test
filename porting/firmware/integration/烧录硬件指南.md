# WQ7036AX/AC 烧录硬件指南(Silero VAD 联调用)

> 2026-09-23 整理。来源:wq-audio SDK 1.3.0.398 的 recover/updater 源码 + 实烧两轮排错。
> 结论:**不需要专用编程器**,一个 USB 转 TTL 小板 + 物奇 Windows 量产工具即可。

## 1. 两个串口,别接混

| | 烧录串口(量产工具用) | 调试串口(看日志/[SHIL] 用) |
|---|---|---|
| 7036AX(BBB 系列) | TX=**GPIO_01**, RX=**GPIO_02**(UART1) | TX=**GPIO_41**, RX=**GPIO_44**(UART0) |
| 7036AC(Hornet 系列) | 同上(全双工引脚同) | TX=**GPIO_98**, RX=**GPIO_93** |
| 波特率 | **115200 握手 → 命令提速,上限 3M** | **固定 2,000,000 8N1**(无流控) |
| 接法 | TX/RX **交叉**, 共地 | 同左 |

出处(SDK 内可 grep 验证):
- `wqcore/pre-project/recover/components/updater/src/updater_interface_uart.c:86`(GPIO_01/02 全双工)
- `wqcore/pre-project/recover/components/updater/bbb/updater_chip.h:30`(调试口引脚)
- `wqcore/components/generic_transmission/src/io_methods/generic_transmission_io_uart.c:96`(2M 8N1)
- `wq-adk/examples/glass/acore/app/readme.md`(官方参考配置表)
- `wq-adk/tools/gprof/readme.md:47`("接好串口,2M波特率")

另有**单线半双工** GPIO_104(充电盒产测用,平时用不到)和 USB CDC 路径
(`updater_interface_usb.c`,官方 Demo 板上的 USB 烧录口即走此路径)。

## 2. 怎么进下载模式(recover)

SDK `recover/bbb/defconfig` + `recover/bbb/acore/main.c:195`:

- **上电/复位瞬间 GPIO_101 为高电平 → 进入 recover 下载模式**
- 进入后等上位机命令,**10 秒无命令自动跳回应用固件**(`CONFIG_RECOVER_DOWNLOAD_TIMEOUT=10`)
- 具体到板子上:看板上有没有烧录按键/跳帽;官方 Demo 板 V3.0 有专用下载口和跳帽组

**不进下载模式就点烧录 → 量产工具报 `burn fail: send ram fail: TIMEOUT!`(进度 0%,约 2 秒退出)。**
这不是固件问题,是芯片根本没在下载模式里应答。

## 3. 实烧两轮排错记录(时间线)

| 轮次 | 现象 | 根因 | 处置 |
|---|---|---|---|
| 第 1 轮 | 烧录 2 秒即结束,报错 | 固件按 **7036AC** 编,板子是 **7036AX**,型号不匹配被工具拒 | 按 7036AX 重编(见 README §7036AX) |
| 第 2 轮 | `send ram fail: TIMEOUT!` 进度 0% | 芯片未进下载模式/串口未通,与 wpk 内容无关 | 按平时烧参考固件的同样操作进下载模式再烧 |

**对照实验**:拿一块确定能烧的参考 wpk(如同版本 stereo.dac)走一遍同样操作——
参考固件也 TIMEOUT = 操作/接线问题;参考能烧我们的不能 = 把两份 wpk 的
memory_config.json 对比反馈回来。

## 6. 烧录成功后的 HIL 验收

1. 日志口接 USB-TTL,串口助手开 **2000000 8N1**;
2. 上电后调试串口应打出 `[SHIL] begin windows=40`,随后 40 行
   `[SHIL] win=NN p=X.XXXX`,结尾 `[SHIL] end wins=40`;
3. 保存输出为文本,跑 `python3 hil_parse.py <日志> golden_prob.f32`,验收线最大偏差 < 0.1;
4. 无麦克风不影响——HIL 用固件内嵌 golden 音频自回环,不依赖外部拾音。
